# MiniMax × OceanBase：规有所依——面向软件持续演进的 SDD 上下文管理系统技术说明书

## 1. 系统架构与模块结构

面向软件持续演进的 SDD（Spec-Driven Development，规格驱动开发）上下文管理系统旨在消除 AI 辅助研发中的“规格漂移”、“过时约束”与“上下文割裂”问题。系统以微型交易结算定价引擎为载体，在统一的工程上下文中实现了闭环的自动化规格推演。

系统分为四个核心层次：
```text
+--------------------------------------------------------------------------+
|                  CLI & SDD Orchestrator (sdd_agent.py)                   |
+--------------------------------------------------------------------------+
       |                                |                            |
       v                                v                            v
[1. 工程资料与检索层]          [2. 任务状态与记忆层]       [3. 大模型代码合成层]
 OceanBase / seekdb                PowerContext                    MiniMax
 存储: 业务规格/源码/测试       保存: 任务进度/阶段检查点    输入: 结构化 SDD 上下文
 检索: 多模态/关键词分块索引     复用: 进程重启后 --resume    输出: 严格遵从规格的代码补丁
+--------------------------------------------------------------------------+
|                 4. 业务工程目标验证层 (business_project)                  |
|          target_code.py (定价引擎) <---> test_target.py (pytest)         |
+--------------------------------------------------------------------------+
```

## 2. 核心技术结合与职责分工

| 参与技术 | 承担职责与技术实现 | 验证核验依据 |
| :--- | :--- | :--- |
| **OceanBase / seekdb** | **工程资料分块存储与精准上下文检索**<br>通过标准 MySQL 协议接入 OceanBase / seekdb，将 `specs.md`、`target_code.py` 与 `test_target.py` 解析为分块物料入库；根据任务描述执行检索，提取本次修改适用的 SPEC 条目与对应测试。支持规格动态更新与即时感知。 | 数据库表 `sdd_project_materials`，以及动态规格变更注入后能够即时检索到最新内容的验证记录。 |
| **PowerContext** | **跨会话/跨进程任务状态持久化与断点续做**<br>接入 PowerContext 上下文管理服务，在任务流转中持久化记录 `status`、`completed_tasks`、`pending_tasks`、`validation_results` 与代码 Diff。支持命令行 `--resume` 恢复已保存的任务状态。 | 进程退出重启后，`--resume` 能够无损恢复 `COMPLETED` 状态与回归测试快照。 |
| **MiniMax** | **基于规格驱动的代码修改与补丁生成**<br>接入 MiniMax 大模型服务，接收由 OceanBase 检索召回的规格、现有源码及测试用例组装而成的提示词，在遵守已有基线行为（SPEC-001~003）的前提下，合成满足 SPEC-004（异常校验）与 SPEC-005（封顶保底）的合规实现。 | 开发日志 `minimax_dev_record.json`，以及修改前 4 失败 3 通过 $\to$ 修改后 7 测试全部转绿的执行日志。 |

## 3. 上下文选择方式 (Context Selection Strategy)

1. **分块建库 (Ingestion)**：
   - 规格文档按 `[SPEC-xxx]` 锚点进行语义分块，提取规格编号与核心关键词。
   - 源代码与测试用例按类与函数签名提取符号及调用依赖。
2. **多维关联检索 (SDD RAG)**：
   - 给定开发任务（如参数校验与金额封顶），引擎从数据库中同时命中适用的规格说明条目、待修改的代码符号文件、以及用于验证该功能的 pytest 测试用例。
3. **动态感知非静态硬编码**：
   - 若在规格库中新增或修改规格（例如调整限额数值），系统重新导入后即刻返回最新规格内容，保证工程上下文的真实与新鲜度。
